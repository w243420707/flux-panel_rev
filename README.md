# flux-panel_rev

`flux-panel_rev` 是一个基于 go-gost 的流量转发面板，仓库内包含面板端和节点端，适合在 VPS 上快速部署、测试和二次开发。

## 项目功能

- 面板端：React/Vite 前端、Spring Boot 后端、MySQL 数据库。
- 节点端：基于 go-gost 改造的节点程序，支持通过 WebSocket 接入面板。
- 节点管理：支持创建节点、查看节点状态、生成节点安装命令。
- 节点重启：管理员可直接重启 VPS，或按小时设置定时重启；每轮自动增加 `0～59分59秒` 随机延迟，设置为 `0` 关闭。
- VPS 累计使用记录：换 IP、普通重启和节点更新持续累计整机上下行流量与使用时长；更换 VPS 或重装系统后新建记录，每个节点只保留当前和前两台。
- 节点资源保护：节点安装或更新时会安全检查并补充 Swap，面板实时显示 CPU、内存和 Swap 使用率。
- 节点被墙监测：由独立 Android 大陆探针回报状态，面板不再执行内置国内/国际 TCP 探测。
- 独立 Android 大陆探针：单独仓库提供 APK，按节点配置的多个 TCP 端口检测并批量上报状态；标记为 Oracle 的节点在面板收到不可达报告后，由面板直接通过 OCI 更换临时公网 IPv4。
- 转发管理：支持端口转发、隧道转发、TCP/UDP 转发、多入口、多出口转发，以及转发批量删除。
- 负载分摊：新增隧道可选择多个入口节点和多个出口节点，多目标或多出口时自动使用轮询分摊。
- 高吞吐默认：隧道转发默认使用适合公网大流量节点的 `mtls` 复用链路，并自动配置 keepalive 和缓冲参数。
- 用户管理：支持用户、套餐、隧道权限和转发数量控制。
- 流量统计：支持入站/出站流量统计，支持单向或双向计费模式。
- 限速管理：支持按用户、隧道维度配置限速规则。
- Cloudflare DNS/DDNS：支持隧道入口单个或多个域名绑定、节点公网 IP 自动更新、A/AAAA 差异同步和定时检查。
- Cloudflare DNS 智能池：自动解析 APK 确认正常的全部节点 IP；被墙 IP 立即移除，节点更换 IP 并恢复后自动重新加入，不再使用固定 70%/30% 备用池和轮换策略。
- 自动部署：支持 VPS 一键安装、更新、卸载、状态查看、日志查看、证书续期和 Docker 缓存清理。
- 运行维护：面板容器后台运行并随 Docker 自动恢复，节点端使用 systemd 开机自启。
- 长期复用：面板前后端从本仓库源码构建，不再依赖第三方面板镜像；节点端资源由独立公开仓库长期托管。
- Android 探针仓库：`flux-panel-android-probe`，不参与面板 Docker 构建，也不接入节点转发配置。

## 双仓库维护规则

- 主仓库：`flux-panel_rev`，维护面板、后端、节点端源码和部署逻辑。
- 节点资源仓库：`flux-panel-node-assets`，维护节点安装脚本、校验文件和 amd64/arm64/armv7/armv6 二进制。
- 只要涉及节点端修改，两个仓库必须同步更新，不能只修改主仓库。
- 节点端版本、安装脚本、二进制和 `SHA256SUMS` 必须保持一致；发布前需要完成四种架构校验。
- 纯面板功能修改可以只更新主仓库，不影响节点资源仓库。

## 部署教程

### 面板端部署

统一使用下面这一条命令：

```bash
curl -L https://raw.githubusercontent.com/w243420707/flux-panel_rev/refs/heads/main/deploy.sh -o deploy.sh && chmod +x deploy.sh && sudo ./deploy.sh install
```

运行后会进入交互菜单：

```text
1. 安装 / 重装
2. 更新并重新构建
3. 卸载
4. 查看状态
5. 查看日志
6. 续期证书
7. 清理 Docker 缓存
0. 退出
```

安装时按提示输入面板域名。使用 HTTPS 时，请先把域名 A/AAAA 记录解析到当前 VPS，并确保 VPS 安全组或防火墙放行 `80` 和 `443` 端口。脚本会自动检查解析、配置 Nginx、申请 Let's Encrypt 证书并设置自动续期。

默认信息：

- 部署目录：`/opt/flux-panel_rev`
- 默认账号：`admin_user`
- 默认密码：`admin_user`
- 首次登录后请立即修改默认密码。

脚本会自动处理：

- 识别 Linux 发行版、CPU 架构、包管理器、init system 和虚拟化环境。
- 安装 Docker、Docker Compose、Nginx、Certbot、Git 等环境。
- 拉取当前仓库源码并构建前端、后端镜像。
- 前端依赖使用 `pnpm-lock.yaml` 锁定版本，降低后续构建漂移风险。
- 使用 Docker Compose 后台启动 MySQL、后端、前端等服务。
- 配置 Nginx 反向代理和 HTTPS 证书。
- 面板端 Docker 日志循环保存 `50MB`，超过后旧日志自动删除；同时可清理无用构建缓存和旧镜像。

### 面板端更新

仍然运行统一命令，进入菜单后选择 `2. 更新并重新构建`。

```bash
curl -L https://raw.githubusercontent.com/w243420707/flux-panel_rev/refs/heads/main/deploy.sh -o deploy.sh && chmod +x deploy.sh && sudo ./deploy.sh install
```

更新会通过 `git fetch --tags --prune --force` 拉取分支和标签，默认部署 `main`，也支持用 `DEPLOY_REF`/`--ref` 指定分支、标签或 commit。更新时会比较上次成功部署的提交和当前提交，只重新构建发生变化的前端或后端镜像，并强制重建容器自动应用最新代码，同时保留数据库数据；默认使用官方/全球源，不再预设国内镜像；Maven 和 pnpm 依赖缓存会被复用，且默认不再额外拉取基础镜像，减少海外 VPS 上的重复下载耗时；更新完成后只执行轻量清理，避免低配 VPS 在清理 Docker build cache 时出现 SSH 卡顿或断连。

仍然运行统一命令，进入菜单后选择 `3. 卸载`。

curl -L https://raw.githubusercontent.com/w243420707/flux-panel_rev/refs/heads/main/deploy.sh -o deploy.sh && chmod +x deploy.sh && sudo ./deploy.sh install

### Android 大陆探针

Android 探针是独立工程，不需要安装到 VPS。通过独立仓库的 GitHub Actions 构建 `app-debug.apk` 后，安装到大陆网络出口的 Android 手机或模拟器中。

新版 APK 默认使用“面板同步”模式：在 Cloudflare DNS 页面复制 Android 探针 API Key，填入 APK 的面板地址和 API Key，APK 会自动拉取节点及最新 IP/域名，并批量回报检测结果。面板收到不可达结果后会复用 Cloudflare 智能解析逻辑移除不可达 IP；已绑定 OCI 账号和实例的 Oracle 节点由面板直接调用 OCI 更换临时公网 IPv4。探针不会收到 OCI 私钥或换 IP API 地址。持续不可达时，面板按节点最小间隔重试，留空按 3 分钟处理且实际不低于 3 分钟；恢复报告和旧公开回调不会触发 OCI 操作。保留型公网 IP 不会自动删除。

APK 支持 IP 和域名、全局多个 TCP 端口（例如 `22,443,500`）、全局检测间隔和每端口检测次数。每个端口按顺序检测，成功一次即通过；任一端口不通过，节点才判定为不可达。域名每轮重新解析，面板同步失败时保留本地缓存。

不接面板时仍可使用手动节点模式。手动节点不可达后可以按冷却时间调用面板的旧公开回调，例如 `/api/remote/change-ip/{token}`；该回调只标记不可达，不执行 OCI 换 IP。未绑定 OCI 实例的普通面板节点不会自动换 IP。

APK 必须运行在大陆网络出口，海外 VPS 或海外模拟器不能代表大陆访问结果。首次运行请允许通知，并点击“开启通知、后台运行和忽略电池优化”。

### Oracle Cloud 自动换 IP

管理员先在“Oracle 账号”中填写账号名称、OCI config 内容和对应的 PEM 私钥，并测试连接。面板会从 config 自动读取 User OCID、Tenancy OCID、API Key 指纹和区域。私钥加密保存在面板数据库中，不会下发给 APK；部署目录 `.env` 中的 `OCI_ENCRYPTION_KEY` 必须随数据库一起备份。

编辑节点时打开“是否为 Oracle 节点”，选择 OCI 账号和具体实例。实例通过 OCID 绑定，公网 IP 变化后仍指向同一实例。OCI API 用户需要读取实例、网卡、私有 IP，并具有在目标 compartment 使用私有 IP 的权限；可参考 [Oracle Core Services Policy Reference](https://docs.oracle.com/en-us/iaas/Content/Identity/Reference/corepolicyreference.htm) 配置。

自动换 IP 仅处理实例主网卡主私有 IP 上的临时公网 IPv4。保留型公网 IP 不会删除；旧 IP 删除后若 OCI 无法创建新 IP，实例可能暂时没有公网 IPv4，节点卡片会显示本次操作失败。

### 节点端部署

推荐在面板中创建节点后，从“节点管理”页面复制自动生成的节点安装命令执行。

节点管理页面提供两个安装按钮：

- `GitHub 安装`：从公开节点资源仓库下载脚本和节点程序，适合海外 VPS。
- `本地安装`：从当前面板的 `/node/` 资源地址下载，适合节点到面板的 GitHub 访问不稳定时使用。

安装脚本会保存本次选择的资源来源，节点执行 `update` 时会继续使用同一来源，不会自动切换。

节点安装脚本会自动：

- 自动识别 Linux CPU 架构，并从独立节点资源仓库下载对应节点端 `gost` 程序。
- 写入 `/etc/gost/config.json` 和 `/etc/gost/gost.json`。
- 创建 `gost.service`。
- 设置 systemd 开机自启和后台运行。
- 将节点日志写入 `/var/log/gost/gost.log`。
- 配置 logrotate，节点端日志循环保存 `50MB`，超过后旧日志自动删除。
- 保留服务器已有 Swap；没有可用 Swap 时，根据内存和剩余磁盘自动创建 `2GB`、`4GB` 或 `8GB` Swap，并设置 `vm.swappiness=10`。

Swap 是内存不足时的缓冲，可以降低节点进程被 OOM 强制终止的概率，但不会替代正常的内存和连接故障修复。安装器不会执行 `swapoff -a`，不会删除服务器已有 Swap；磁盘不足或 VPS 不允许启用 Swap 时只会给出警告，不会阻止节点安装。

### 节点重启与定时重启

节点升级到 `3.1.6` 后，管理员可在节点卡片点击“重启 VPS”直接重启整台服务器，无二次确认。节点必须在线，并按标准安装方式以 root 运行在 systemd 管理的 Linux VPS 上；容器中的节点不支持重启宿主机。所有经过该 VPS 的连接会短暂中断，提示“已收到重启指令”只代表节点接受了请求，恢复情况以节点重新上线为准。

“定时重启”只需填写整数小时数：`1～720` 开启，`0` 关闭。每个周期独立增加 `0～3599` 秒随机延迟，例如 `24` 小时表示 `24小时～24小时59分59秒`。在线节点从保存时开始计时；离线时暂停，重新上线后开始完整的新周期。卡片和设置弹窗显示下一次计划时间。

计划保存在面板数据库，由面板后台执行，关闭浏览器不影响任务。面板停机期间不会执行；重启面板后保留尚未到期的计划，已错过的计划从节点重新连接时重新计时，不集中补发。请求被拒绝、执行失败或回执超时后暂停该节点计划，等待节点重新上线或重新保存设置，不自动重复发送重启指令。手动重启也会在节点重新上线后重新计算周期。

升级面板后，还需更新各 VPS 的节点程序才能使用重启功能；旧节点的转发功能保持可用。后端启动时会自动补齐定时设置字段，已有节点默认关闭定时重启。

### VPS 累计流量与三台循环历史

面板更新到 `1.3.66`、节点更新到 `3.1.7` 后，第一次确认接入时从 `0` 开始统计。节点卡片显示累计上传、累计下载、两者合计和累计使用时长；“本次开机时间”仍表示这次启动后经过多久。累计使用时长从开始统计到更换 VPS 计算，包含关机或断网时间；离线时也保留最后保存的累计流量。

普通重启、换 IP、节点程序更新不会新建使用记录。面板结合 VPS 硬件 UUID 和系统 machine-id 的哈希指纹核对身份，MAC 仅作辅助；硬件身份变化或重装系统导致系统身份变化时，新建记录并封存旧记录。标识不足、历史机器再次连接或同一节点配置被多台机器同时使用时，会先显示待确认，不把新旧机器的流量混在一起；管理员在“VPS 使用记录”中选择“仍是同一台”或“已更换／重装”。

每张节点卡片最多保存当前、上一台、上上一台三份记录，包含开始时间、更换时间、累计上下行、总流量和总时长。产生第四份时会从数据库删除最旧的一份；删除节点卡片也会一并删除这些记录。更换时间以面板实际识别或确认新机器的时间为准。

节点每 `5` 秒独立采集全部非 `lo*` 网卡，与现有网卡统计口径一致，包含系统和其他程序产生的流量，不套用转发套餐倍率，也不等同于云厂商账单。节点断开面板时继续累计，重连后补报最新绝对值；正常重启前会补采样保存。节点仅保存 `/etc/gost/vps-usage.json` 和最多一份 `.corrupt` 备份，不保存逐次采样明细，安装器更新会保留该文件。

统计文件丢失、损坏或恢复旧快照不会清零面板已有总量；面板会对齐新的计量起点后继续，无法核实的异常期间流量不会凭空补算。突然断电前尚未采集或保存的最后一小段数据无法还原。机器镜像完全复制且所有身份信号相同时无法保证自动区分，因此不能只凭 MAC 宣称绝对唯一。

### 转发使用

- 新增隧道时只需要选择入口节点和出口节点，协议会自动使用优化后的高吞吐默认值。
- 一个隧道可以选择多个入口节点，新增转发后会同时下发到所有入口节点。
- 一个隧道可以选择多个出口节点，多出口时转发会自动轮询分摊。
- 一个转发可以填写多个目标地址，多目标时也会自动轮询分摊。
- 批量导入转发采用“先保存、后下发”：某个入口或出口节点离线时，导入仍会成功；转发会先显示“待确认”，后台会持续补发，所有节点恢复后自动变为“正常”。
- TCP 和 UDP 服务会同时创建，使用 UDP 场景时请确认 VPS 防火墙和安全组已放行对应 UDP 端口。
